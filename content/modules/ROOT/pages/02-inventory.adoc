= Inventário Ansible

O inventário define quais máquinas o Ansible vai gerenciar e como se conectar a elas.

== O que e um Inventario?

O inventário e um arquivo que lista os hosts (máquinas) que o Ansible vai configurar. Ele pode ser um simples arquivo INI ou um arquivo YAML.

== Configurando o Inventario

Edite o arquivo `inventory/hosts.ini` com os dados da sua VM 2.

=== Opcao A: Autenticacao por Chave SSH (recomendado)

[source,ini]
----
[webservers]
vm2 ansible_host=192.168.56.11 ansible_user=seu_usuario ansible_ssh_private_key_file=~/.ssh/id_rsa
----

=== Opcao B: Autenticacao por Senha

[source,ini]
----
[webservers]
vm2 ansible_host=192.168.56.11 ansible_user=seu_usuario ansible_ssh_pass=sua_senha
----

[IMPORTANT]
====
Substitua `192.168.56.11` pelo IP real da sua VM 2, e `seu_usuario` / `sua_senha` pelas credenciais corretas.
====

== Variáveis do Grupo

As variáveis do grupo `webservers` ficam em `inventory/group_vars/webservers.yml`:

[source,yaml]
----
nginx_enable_official_repo: false
nginx_port: 80
----

Essas variáveis controlam:

* `nginx_enable_official_repo` -- se `false`, instala o nginx do repositório padrão do CentOS. Se `true`, adiciona o repositorio oficial do nginx.org.
* `nginx_port` -- porta em que o nginx vai escutar. Padrao: `80`.

== Testando o Inventário

Verifique se o Ansible consegue se conectar:

[source,bash]
----
ansible webservers -m ping -K
----

Voce deve ver uma resposta `SUCCESS` em verde:

[source]
----
vm2 | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
----

[WARNING]
====
Se o comando falhar, verifique:

* O IP esta correto?
* As credenciais estão corretas?
* O SSH esta acessível na VM 2?
====
